# Direction: north stars, scorecard, gates and risks

How we know the project is going the right way, not only that it is going. This document is read at every phase gate.

## 1. Vision and anti-goals

**Vision.** One open source database a whole dev team can run alone: work items, docs, specs, designs, deployments and their relationships, always current, queryable by text, meaning and time, with agents as first-class, permission-bound teammates.

**Anti-goals.** Not a general-purpose Postgres replacement. Not an LLM host: the core never calls a model. Not a Jira or Confluence clone feature for feature: we build the capabilities a modern team needs on one kernel. Not a place where an agent can act beyond a grant.

## 2. North-star scenarios

Each scenario is an executable acceptance test created in Phase 1 as a pending specification, and is re-run at every gate. A scenario passes only end to end through public interfaces.

| Id | Scenario | Passes in phase | Acceptance |
|---|---|---|---|
| NS1 | **Crash safety**: kill the process during a burst of mixed writes at a random moment, restart | 1 (log level), 2 (all engines) | Every acknowledged write present, no partial change set, scrubbers clean |
| NS2 | **History question**: "when did this feature start being built?" and "when did I create t.go?" | 7 | Dates, actors and evidence exactly equal to a scan of the log; permissions respected |
| NS3 | **Drift fixed**: a deployment changes a rate limit that a runbook states | 8 | Drift detected within the SLA, proposal created on a branch, accepted, claim re-verified |
| NS4 | **Read-only answer**: a person asks "how does export streaming work?" and an agent answers | 8 | Answer cites existing, permitted sources that contain supporting text; agent produced zero writes |
| NS5 | **Agent cannot exceed its grant**: an agent attempts writes, a forbidden read, and a privilege escalation through an injected instruction in a document | 4 (policy), 8 (agents) | All blocked and audited; hash chain verifies |
| NS6 | **Team in one tool**: a PM, BA, designer, developer and two agents run a sprint end to end in Lattice | 9 | Traceability from requirement to deployment is one query; no external tracker used |
| NS7 | **Offline then merge**: two replicas edit the same page and ticket offline | 3 | Both replicas converge; semantic conflicts surfaced as objects |
| NS8 | **We build Lattice with Lattice**: the project's backlog, docs, designs and decisions live in Lattice | 6 | 100 percent of new work items and docs created in Lattice from the Phase 6 gate on |

## 4. Phase gate process

Defined in the [README](README.md). Gate evidence is generated by `xtask gate --phase N`. A gate review is signed by two maintainers and records: criteria results, waivers (with owner and expiry), north-star re-run, risk register changes, and the go, pivot or stop decision.

### Kill and pivot triggers

| Trigger | Phase | Response |
|---|---|---|
| Simulation cannot be made deterministic | 1 | Stop feature work; redesign the seams or the simulator |
| Planted-bug detection below 80 percent | 1 | Strengthen invariants and workloads before Phase 2 |
| Native SQL coverage cannot reach the declared subset at acceptable cost | 2 | Evaluate a Postgres fork for the SQL layer by ADR |
| Cross-engine atomicity (I2) cannot hold under simulation without a performance collapse | 2 | Revisit the unified-WAL design |
| Convergence failures (I5) not resolvable with the chosen text CRDT | 3 | Switch CRDT implementation per the Phase 1 ADR fallback |
| Agent-driven judging cost or latency unacceptable for drift SLAs | 8 | Pull the optional model plugin forward (Phase 11) |
| Drift false positives above the noise budget after tuning | 8 | Narrow drift kinds to deterministic ones only |
| No design partner can complete a sprint in Lattice | 9 | Re-scope packs with partner feedback before cluster work |

## 5. Initial risk register

| Id | Risk | Likelihood | Impact | Mitigation | Early signal |
|---|---|---|---|---|---|
| R1 | Scope too large for the team | High | High | Phases are independently useful; gates cut scope with evidence | Gate slips twice |
| R2 | Simulation discipline erodes | Medium | High | Lint bans, determinism self-check, planted bugs | E1-1 trends down |
| R3 | Native SQL engine takes too long | Medium | High | Declared subset, conformance-driven, Postgres-fork fallback ADR | Subset pass rate stalls |
| R4 | Built-in IdP security flaws | Medium | High | Conformance suite, fuzzing, external review before GA | Review findings |
| R5 | Agents unavailable or poor at extraction and judging | Medium | Medium | Rules cover deterministic parts, queue SLOs, optional model plugin | Queue age grows |
| R6 | Eval datasets mislead | Medium | Medium | Mutation-based plus consented real data, override rates in production | Offline and online metrics diverge |
| R7 | Format or wire churn after release | Medium | High | Freeze corpus, RFC and ADR process, compatibility policy | Corpus break attempts |
| R8 | Performance targets missed | Medium | Medium | Baselines in Phase 1, benchmark gates each phase | Regression trend |
| R9 | Layer discipline erodes | Medium | Medium | `check-layers` in CI | Waiver requests |
| R10 | UX does not fit real teams | Medium | High | Prototype-driven research, design partners from Phase 6 | Partner churn |
| R11 | Model licences or ONNX parity block the optional plugin | Medium | Low | Plugin is optional; core never depends on it | Spike failure |
| R12 | Maintainer bandwidth | Medium | High | Governance, CODEOWNERS, clear contribution path | Review latency |

## 6. Feedback loops

- **Monthly demo** against the north-star list.
- **Design partners** (one per role: PM, BA, designer, developer, QA) from Phase 6; their tasks become evals and scenarios.
- **Dogfood review** each gate: what hurt when using Lattice to build Lattice becomes backlog.
- **Override and rejection data** from agent features (Phase 8 onward) feeds calibration and dataset refresh.
- **Decision log**: every direction change is an ADR; the gate package lists new ADRs since the last gate.
