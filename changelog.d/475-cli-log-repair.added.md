`lattice log repair [--dir DATA_DIR] [--wal NAME] [--apply]` reports damage in a write-ahead log. Without `--apply` it changes nothing and exits 1 when the log holds damage the command cannot fix. With `--apply` it truncates only a torn tail, the bytes recovery itself would discard, after copying the whole segment to `<segment>.repair-backup` and verifying the copy. It refuses interior damage, a checksum-valid record with the wrong LSN, a missing segment, a link anywhere on the path or a live writer holding `LOCK`. It never prints record payloads. Re-verification opens the log with the server's recovery. Not done: repairing a checksum-valid record with the wrong LSN (formats/wal-v1.md, issue 441); that stays a manual procedure.
